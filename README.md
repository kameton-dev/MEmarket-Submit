# MEmarket Submit

## Аккаунты разработчиков

- Регистрация и вход: `/developer/register` и `/developer/login`.
- Личный кабинет: `/developer`; аккаунт получает приложения только после одобрения первой заявки.
- В кабинете можно сменить пароль, а также удалить аккаунт с подтверждением никнейма. При удалении можно отдельно выбрать, удалять ли опубликованные приложения из каталога; без выбора они останутся без владельца.
- Новое приложение отправляется через общую форму загрузки после входа. Для уже опубликованного приложения доступна загрузка обновления из кабинета.
- Карточку опубликованного приложения можно редактировать из кабинета разработчика без загрузки пакета и без модерации; изменения записываются в репозиторий и индекс обновляется через `memarketrepo update`.
- Версия берётся из `Version` в `WMAppManifest.xml`, `Identity Version` в `AppxManifest.xml` или манифесте APPX Bundle. Для обновлений поддерживаются числовые версии из 1–4 компонентов; новая версия должна быть строго больше текущей версии пакета в репозитории.
- После одобрения обновления сохраняются четыре самые новые версии пакета; при публикации пятой самая старая версия удаляется.
- Запросы на привязку существующего приложения отправляются из личного кабинета и рассматриваются модератором на `/admin`. Подтверждение может сменить текущего владельца, поэтому перед одобрением проверьте приложенные доказательства.

SQLite-таблицы и недостающие столбцы создаются при запуске. Приложения, добавленные до появления аккаунтов, остаются без владельца, пока модератор не одобрит запрос на подтверждение авторства.

Проверка сравнения версий и чтения манифестов: `python -m unittest discover -s tests`.

Перед запуском задайте секреты окружения:

- `FLASK_SECRET_KEY` — постоянный случайный секрет для подписи сессионных cookie.
- `ADMIN_USER` и `ADMIN_PASSWORD` — учётные данные модератора.
- `MEMARKET_REPO_PATH` — путь к рабочему каталогу MEmarket-Basic.
- `SESSION_COOKIE_SECURE=1` — включите при работе сайта по HTTPS.

Не храните настоящие значения в исходном коде или в Git. Перед публикацией задайте новый пароль модератора: прежний пароль следует считать раскрытым. Если он уже попадал в историю Git, одной правки файла недостаточно — пароль всё равно нужно сменить. При локальном запуске задайте новые значения в PowerShell до запуска приложения:

```powershell
$env:ADMIN_USER = "имя_модератора"
$env:ADMIN_PASSWORD = Read-Host "Пароль модератора"
$env:FLASK_SECRET_KEY = "длинный_случайный_секрет"
python app.py
```

Для GitHub Actions добавьте секреты в настройки репозитория и передавайте их процессу деплоя через secrets. На сервере задавайте переменные окружения в конфигурации службы или хостинга. Если `ADMIN_USER` или `ADMIN_PASSWORD` не заданы, админ-панель будет отключена. Используйте её только через HTTPS.

Пароли разработчиков сохраняются только в виде хеша. Сессии разработчиков подписываются Flask и защищены от чтения JavaScript; POST-формы аккаунта проверяют CSRF-токен.
